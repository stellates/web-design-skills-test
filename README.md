# web-design-skills-test

生成AIによるWeb画面生成に、Webデザイン用Skillを適用した場合と適用しなかった場合で、生成結果がどのように変化するかを比較・検証するためのリポジトリです。

## 目的

生成AIにWeb画面を実装させる際、プロンプトやSkillによって一定の設計方針を与えることで、初回生成物の品質や扱いやすさがどのように変化するかを継続的に観察します。

このリポジトリでは、単に完成した画面の見た目を評価するのではなく、

* 要件の解釈
* 情報構造
* 操作性
* 可読性
* デザインの一貫性
* 不要な要素の有無
* 実装の扱いやすさ
* 初回生成物としての完成度

などを含めて比較します。

目的は、特定のデザインや実装方式を正解として固定することではありません。

生成AIにどのような指示や制約を与えると、Web画面生成がより安定し、後続の開発につなげやすくなるのかを実験的に確認することを目的とします。

## 基本的な実験方法

原則として、同一または同等の画面要件に対して、条件を変えた生成結果を比較します。

代表的な比較例:

1. Skillを使用しない
2. Skillを使用する
3. 異なるバージョンのSkillを使用する
4. 必要に応じて、その他の条件を変更する

比較においては、可能な限り画面要件そのものを維持し、変更した条件が生成結果へ与える影響を観察します。

同一条件で複数回生成し、生成ごとの揺らぎを確認する場合もあります。

## Skillの管理

WebデザインSkillは、ファイル単位でバージョン管理します。

例:

```text
design_v1.0.0.md
design_v1.1.0.md
design_v1.2.0.md
design_v2.0.0.md
```

新しいバージョンを作成した場合も、過去のSkillファイルは削除しません。

既存ファイルを更新して履歴だけをGitに残すのではなく、それぞれのバージョンを独立したファイルとして保存します。

これにより、過去のSkillをそのまま使用して比較実験を再現できる状態を維持します。

## 初版

最初のWebデザインSkillは以下とします。

```text
design_v1.0.0.md
```

以後、実験結果を踏まえて改善を行う場合は、新しいバージョンとして追加します。

## バージョンの扱い

Skillの変更内容に応じてバージョンを更新します。

厳密なSemantic Versioningへの準拠を目的とはしませんが、概ね以下のように扱います。

```text
v1.0.0
```

初版または大きな方針の基準となる版。

```text
v1.1.0
```

既存方針を維持した比較的大きな改善や追加。

```text
v1.1.1
```

表現修正や小規模な調整。

```text
v2.0.0
```

Skillの考え方や構成を大きく変更した場合。

実験の再現性を優先するため、古いバージョンを新しい内容で上書きしないことを原則とします。

## リポジトリ内のルール

このリポジトリでは、以下を基本ルールとします。

* 過去のSkillを削除しない
* 過去の実験結果を、後から良い結果だけに整理し直さない
* Skillを変更した場合は別バージョンとして保存する
* 比較実験では、可能な限り同じ要件を使用する
* 実験条件が異なる場合は、その違いが分かるように記録する
* 成功例だけでなく、失敗例や悪化した例も残す
* 結果に合わせて過去のSkillや要件を書き換えない

## 実験結果について

このリポジトリでは、Skillの有効性を証明すること自体を目的としません。

Skillを利用した結果、

* 改善した
* ほとんど変化しなかった
* 一部だけ改善した
* 別の問題が発生した
* Skillなしの方が良かった

といった結果も、そのまま実験結果として扱います。

意図した結果だけを残すのではなく、生成AIの挙動を観察できる記録として蓄積します。

## 評価

評価方法は、実験の進行に応じて変更・追加する可能性があります。

基本的には、生成された画面について、

* 要件を適切に反映しているか
* 情報構造が自然か
* 操作しやすいか
* 読みやすいか
* 不要な要素が増えていないか
* 見た目に一貫性があるか
* 修正や拡張を行いやすいか
* 初回生成物として利用可能な水準にあるか

といった観点から確認します。

必要に応じて、新しい評価観点を追加します。

特定の評価方法をREADME上で固定せず、実験の目的に合わせて柔軟に変更できるものとします。

## Skillの内容について

各Skillの具体的な設計方針、技術選択、デザインルール、実装ルールなどは、それぞれの `design_vX.Y.Z.md` に記述します。

READMEでは、それらの内容を前提としません。

そのため、将来Skillの内容や方向性が大きく変化した場合でも、このリポジトリの目的と運用ルールは継続して利用できることを前提とします。

## このリポジトリで残したいもの

最終的なSkillだけではなく、そのSkillへ至るまでの過程も保存します。

残す対象には、たとえば以下があります。

* Skillの各バージョン
* 比較に使用した要件
* Skill利用有無による生成結果
* バージョン間の生成結果
* 実験時の条件
* 気づいた問題
* 改善理由
* 想定外の結果

これらを残すことで、最終版だけを見ても分からない「なぜそのルールになったのか」を後から確認できる状態を目指します。

## ゴール

この実験のゴールは、唯一の正しいWebデザインSkillを完成させることではありません。

生成AIによるWeb画面生成に対して、

**どのような指示が、どのような結果を生むのかを比較可能な形で蓄積し、再利用できる知見にすること**

を目指します。
