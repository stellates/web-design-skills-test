# 画面要件作成テンプレート

このテンプレートは、Web画面を実装する前に、画面要件を整理するためのプロンプトとして使用する。

目的は、デザイン方針そのものではなく、**何を表示し、どのような構成で、どの情報を優先するか**を先に要件化することである。

デザイン上の見た目や実装上のガードレールは、別途 `skills/design_vX.Y.Z.md` のようなDesign Skillで指定する。

---

## AIへの指示

以下の情報をもとに、Web画面の実装に利用できる画面要件を整理してください。

要件に明記されていない機能や情報を、慣例だけを理由に勝手に確定しないでください。

ただし、画面として不足している情報や判断が必要な点は、必要に応じて候補を示してください。

特に、以下を区別してください。

- 必須要件
- 希望要件
- AIが補完してよい範囲
- 未決事項

画面構成について希望がある場合は、Design Skill側へ暗黙に任せず、画面要件として明示してください。

テーマや配色などの見た目と、サイドバー・ヘッダー・カラム構成などのレイアウトは別の判断として扱ってください。

テーマを変更するだけで、主要な画面構成まで変更されることを前提にしないでください。

## 入力項目

以下を分かる範囲で指定する。

### 基本情報

- Webサイト / システム名:
- 画面名:
- 画面の目的:
- 主な利用者:

### 表示したい情報

- 最も重要な情報:
- その他に表示したい情報:
- 一覧表示したい情報:
- 詳細表示したい情報:
- 状態・進捗・通知として見せたい情報:

### 操作

- 主な操作:
- 補助的な操作:
- リアルタイム更新の有無:
- 検索・絞り込み・並び替えの要否:

### 希望レイアウト

以下は必要なものだけ指定する。

- ナビゲーション方式:
  - 例: 左サイドバー / 上部ナビゲーション / ナビゲーションなし / AIに任せる
- ヘッダー:
  - 例: 固定 / 通常 / 最小限 / 不要 / AIに任せる
- メイン領域の構成:
  - 例: 1カラム / 2カラム / 一覧中心 / ダッシュボード型 / AIに任せる
- サマリー・KPI領域:
  - 必要 / 不要 / AIに任せる
- 補助情報領域:
  - 例: 右カラム / 下部 / 不要 / AIに任せる
- 情報密度:
  - 例: 高め / 標準 / 低め
- 主要コンテンツの優先順位:
- 最初の画面内で必ず見せたい情報:

### レスポンシブ要件

- 主な利用端末:
- モバイル対応の必要性:
- モバイル時のナビゲーション希望:
- 横スクロールを許容する要素:

### デザイン・実装条件

ここでは、画面要件として必要な条件だけを指定する。

- 利用するDesign Skill:
- テーマ指定:
- 既存システムとの統一条件:
- その他の実装上の制約:

詳細なデザインルールやCSS実装方針はDesign Skill側に持たせ、ここで重複して定義しない。

### AIが補完してよい範囲

例:

- ダッシュボードとして自然な補助情報は追加してよい
- ナビゲーション項目は必要最小限で補完してよい
- KPIの内容は要件から推測してよい
- 要件にない機能は追加しない

## 出力形式

AIは最終的に、実装へそのまま渡せる形で以下の形式に整理する。

```text
次のWEB画面を作ってください。

- WEBサイト名
  - ...
- 画面名
  - ...
- 概要
  - ...
- 主な利用者
  - ...
- 表示情報
  - ...
- 機能性
  - ...
- レイアウト
  - ナビゲーション: ...
  - ヘッダー: ...
  - メイン構成: ...
  - サマリー/KPI: ...
  - 補助情報: ...
  - 情報密度: ...
- 優先表示
  - ...
- レスポンシブ
  - ...
- AIが補完してよい範囲
  - ...
- その他の制約
  - ...
```

不要な項目は無理に残さなくてよい。

要件として決まっていない内容を、完成した要件のように断定しないこと。

Design Skillを利用する場合は、この画面要件とDesign Skillを組み合わせて実装する。
