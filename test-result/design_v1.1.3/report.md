## v1.1.3で意図した改善

v1.1.2では見た目の完成度は高かったが、以下の問題が確認された。

- 要件にないKPI、機能、管理項目、ナビゲーション等を大量に補完した
- 日本語画面に英語ラベルを多数混在させた
- サービス名の頭文字を使った疑似ロゴ等、情報価値の低い装飾を追加した
- サイト名を複数箇所で異なる表記にして重複表示した
- データソースがないにもかかわらず、自動同期しているように見せる架空処理を追加した

一方、v1.1.0およびv1.1.2程度の独自CSS量は、単一画面や小規模なWeb画面としては一般的なフロントエンド保守の許容範囲と再評価した。

そのためv1.1.3では、独自CSS自体を強く抑制するのではなく、以下を中心にガードレールを再構成した。

- AIが補完してよい範囲を「表示上の設計」に限定する
- 要件にない機能・データ・業務概念を発明しない
- 表示言語を一貫させる
- 情報価値のない疑似ロゴや装飾記号を追加しない
- 同じ名称や意味を不要に重複表示しない
- データソースのない機能を架空処理で完成させない
- 独自CSSは保守しやすい範囲で許容する

## ダッシュボード検証

### 出力

`preview_use_skill.html`

### 良かった点

v1.1.2で見られた要件外補完が大きく抑制された。

画面の主要情報は以下に収まっている。

- 利用中サービス
- 稼働状況
- 最新情報
- 使用量
- 同期状態

`Connections`、`Notifications`、`Settings`、`Add service`、`Estimated cost`、`Budget` 等の要件外機能・指標は追加されなかった。

表示言語も日本語主体で統一され、装飾目的の英語ラベルはほぼ消えた。

また、v1.1.2で見られた `O / G / A / P` のようなサービス頭文字の疑似ロゴも追加されていない。

サイト名はサイドバーに `Using AI Dashboard` と表示し、上部ヘッダーには画面の役割である `AIサービス一覧` を置いている。v1.1.2のように、同じ名称を省略・変形して複数箇所へ重複表示する問題も改善された。

リアルタイム同期についても、架空の `setInterval()` 等を実装せず、`データソース未接続`、`同期待機中`、`未接続` として状態を表現した。

これは、機能要件を満たしたように演出するのではなく、現時点で実装可能なUI状態として正直に表現できている。

### 見た目

v1.1.0やv1.1.2ほどの華やかさはないが、v1.1.1のような「Bulma標準部品をそのまま並べただけ」という印象にもなっていない。

現時点では、

- v1.1.0: 見た目は最も好ましいが、補完が多い
- v1.1.2: 見た目はかなり良いが、要件外補完が大きい
- v1.1.3: 見た目はやや控えめだが、要件遵守・保守性とのバランスが良い

と評価する。

### モックデータの扱い

ChatGPT / Claude / Gemini や、使用量 `62% / 41% / 28%`、稼働状況 `2正常 / 1確認中` 等の値はAIが補完している。

ただしこれは、要件に存在しない新しいKPIや業務概念を追加したものではなく、元々要件に存在する「サービス」「稼働状況」「使用量」を可視化するためのモックデータである。

画面プレビューを成立させるためのサンプル値としては許容範囲と考える。

したがって今後の線引きは、

- 要件にない項目・機能・概念を発明する: NG
- 要件にある項目を表示するためのモックデータを置く: 許容

とするのが自然である。

### 軽微な重複

`利用中のAIサービス` の右側に `稼働状況・最新情報・使用量` と表示しているが、直下のテーブル見出しと内容が重複する。

大きな問題ではないが、「画面を見れば分かる説明を重複させない」という方針には改善余地が残る。

```text
- 概要

- 機能性
  - 最新記事を強調
  - 人気トップ３の記事を紹介
  - 過去記事の一覧画面への遷移を可能とする
- テーマ
  - Litera
- レイアウト

```

### 出力

`preview_use_skill_blog_litera.html`

### 良かった点

レイアウトを「お任せ」としたが、ダッシュボード検証の構成を引きずらず、ブログ・読み物サイトとして自然な構成を選択した。

主な構成は以下。

- ヘッダー
- 最新記事の強調表示
- 人気トップ3
- 過去記事一覧への導線
- フッター

最新記事だけを大きなブロックとして強調し、人気記事はカード化せず罫線ベースの一覧として表現している。

すべてをカード化せず、情報の役割に応じて表現を変えており、v1.1.3のガードレールが特定の画面形式を固定していないことを確認できた。

表示言語も日本語主体で一貫しており、英語を装飾として混在させる問題はない。

また、疑似ロゴや不要な装飾マークも追加されなかった。

要件外の検索、カテゴリ、管理機能、サイドバー等も追加されておらず、要件境界も良好である。

### テーマ適用

Literaの影響により、serif系のタイポグラフィ、白〜薄いグレー基調、罫線中心の落ち着いた読み物サイトになった。

今回の「AI備忘録」に対しては、やや文芸誌・研究ノート寄りの印象になったが、これはSkillの問題というよりテーマ選択の影響が大きい。

重要なのは、テーマ変更によって管理画面の見た目を引きずらず、サイト種別に応じた表現へ変化できた点である。

### ヘッダーの課題

ヘッダーはサイト名 `AI備忘録` と `最新 / 過去記事` のナビゲーションのみで、かなり簡素である。

Litera自体が派手なナビゲーション表現を持つテーマではないものの、今回の貧相さはテーマだけが原因ではない。

サイト名、ナビゲーション、現在位置、ブランド感等の視覚的な整理が弱く、独自CSSを許容しているのであれば、もう少し丁寧に仕上げる余地がある。

ただし、要件外の機能やコンテンツを追加して豪華にするのではなく、既存要素の余白、タイポグラフィ、境界、active状態等を調整して品質を上げるべきである。

### 最新記事見出しの課題

最新記事タイトルは、`clamp()` によって画面幅に応じて大きさを変えているが、実際のタイトル文字数までは考慮していない。

その結果、長い日本語タイトルが不自然な位置で折り返されている。

問題は「見出しが大きいこと」自体ではない。

本質は、AIがレスポンシブ幅は考慮しても、**実際のコンテンツ長と折り返し結果を十分に考慮していない**ことである。

今後は、見出し、ラベル、ボタン等について、実際の文字数と表示幅を踏まえ、不自然な改行や短い孤立行を避ける必要がある。

実装手段としては、状況に応じて以下が考えられる。

- 適切な `max-width`
- `text-wrap: balance`
- フォントサイズ上限の調整
- 行間の調整
- 日本語の改行特性を考慮したCSS

Skillには個別技法を大量に列挙するのではなく、「実際のコンテンツ長を見て折り返しを確認する」という品質原則として入れるのが適切と考える。

### 遷移リンク

最新記事の `記事を読む` は `#latest-title`、人気記事は `href="#"` となっており、実際の詳細ページへは遷移しない。

記事詳細ページのURLは要件に与えられていないため、モックとして理解できるが、意味のないリンクを完成機能のように置く点は改善余地がある。

一方、過去記事一覧は要件で明示されているため `archives.html` へのリンクとして表現されている。

## 独自CSSの再評価

v1.1.0およびv1.1.2のHTML/CSSを一般的なWebデザイナー・フロントエンドコーダーの保守観点から再評価した結果、単一画面や小規模サイトとしては概ね許容範囲と判断した。

問題はCSSの行数そのものではない。

実務上より問題になりやすいのは、以下のような状態である。

- 深すぎるセレクタ依存
- `!important` の乱用
- DOM構造へ強く依存したCSS
- 命名規則のない大量のクラス
- 同じ目的のCSSが多数重複する
- JSがstyle属性を大量に直接操作する
- 同じコンポーネントの亜種が無秩序に増える

v1.1.0〜v1.1.3の独自CSSは、役割単位のクラス名と比較的単純なセレクタで構成されており、この意味では大きな保守問題は確認されていない。

したがって、今後は「独自CSSを減らす」こと自体を目的としない。

Bulma / Bulmaswatchを基盤として利用しつつ、ページ固有の視覚品質を高めるためのCSSは積極的に許容する。

## v1.1.4へ向けた観点

v1.1.3では、要件境界、表示言語、疑似ロゴ、重複表現、架空機能等の問題が大きく改善された。

一方、独自CSSを許容する方針を取るのであれば、見た目の品質はもう一段高めたい。

ここで重要なのは、v1.1.2のように情報や機能を追加して「完成度」を高めることではない。

**同じ要件・同じ情報のまま、既存要素の見せ方を丁寧にすること**を目標とする。

### 視覚品質の改善対象

次版では特に以下を意識させる。

- 余白とセクション間のリズム
- タイポグラフィ
- 見出し・本文・補助情報の階層
- ヘッダーやナビゲーションの仕上げ
- 境界、罫線、背景の使い分け
- hover / active / focus 等の状態
- レスポンシブ時の見え方
- 実コンテンツ長を考慮した折り返し

Skillでは例えば、以下の趣旨を短く追加する方向が考えられる。

> 独自CSSは、画面要件を増やすためではなく、既存の情報構造を読みやすく、自然で、完成度の高い見た目に整えるために使用してください。特に余白、タイポグラフィ、情報階層、折り返し、境界、レスポンシブを丁寧に調整してください。

また、折り返しについては以下の原則が有効と考える。

> 見出し・ラベル・ボタン等は、実際の文字数と表示幅を考慮し、不自然な改行や孤立した短い行を避けてください。

### CSS / JavaScriptのコメント

独自CSSやJavaScriptを保守対象として許容するのであれば、コード上の意図を人間が追いやすくするため、適切なコメントも有効と考える。

ただし、すべての行や自明な処理へコメントを付けるのではなく、以下のような箇所を対象とする。

- ページ固有のレイアウト意図
- フレームワーク標準から外れる調整理由
- レスポンシブ時の特殊な挙動
- JavaScriptによるUI状態変更
- 一見して理由が分かりにくい値や制御

次版Skillでは、例えば以下のような原則を追加する方向を検討する。

> 独自CSSやJavaScriptには、レイアウト意図や特殊な挙動など、後から見て理由が分かりにくい箇所に簡潔なコメントを入れてください。自明な処理への過剰なコメントは不要です。
