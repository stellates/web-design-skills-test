## v1.1.4で意図した改善

v1.1.3は、要件遵守、表示言語、疑似ロゴ、重複表現、架空機能等の抑制に成功し、v1.1.x系列の中で最もバランスが良い結果となった。

一方で、見た目については以下の改善余地が残っていた。

- ダッシュボードは実用的だが、v1.1.0やv1.1.2ほどの完成感・華やかさはない
- ブログのヘッダーが簡素で、ブランド感が弱い
- 長い日本語見出しの折り返しが不自然
- 独自CSSを許容している割に、見た目の仕上げが控えめ

そのためv1.1.4では、v1.1.3の思想を維持したまま、以下を追加した。

- 余白、タイポグラフィ、情報階層、境界、ヘッダー、ナビゲーション、hover / active / focus、レスポンシブ等を丁寧に調整する
- 実際の文字数と表示幅を考慮し、不自然な改行や孤立した短い行を避ける
- 見やすさや使いやすさを高めるための独自CSS利用を明示的に許容する
- CSS / JavaScriptの意図が分かりにくい箇所には簡潔なコメントを入れる
- 要件内の表示を成立させるためのモックデータは許容する

狙いは、要件外の情報や機能を増やさず、同じ要件のまま見た目の品質を上げることだった。

## ダッシュボード検証

### 良かった点

v1.1.3で改善された要件境界は概ね維持された。

表示内容は、利用中AIサービスごとの稼働状況、最新情報、使用量に収まり、v1.1.2で見られた要件外KPIや管理機能の大量追加は再発していない。

日本語主体の表示も維持され、疑似ロゴや過剰な英語ラベル等の表示ノイズも抑えられている。

また、JavaScriptはモバイル時のサイドバー開閉に限定され、データソースがないにもかかわらず同期処理を架空実装する問題も再発していない。

### コメント指示は成功

v1.1.4で追加したCSS / JavaScriptへのコメント指示は、明確に効果が確認できた。

例えば、レスポンシブ時のレイアウト意図や、モバイルナビゲーションが同期処理とは無関係であること等について、簡潔なコメントが追加された。

コメント量も過剰ではなく、意図が分かりにくい箇所を補足する程度に収まっている。

この点はv1.1.4の成功事項として残す。

### 見た目は向上しなかった

今回の主目的であった「見た目の仕上げ品質向上」は達成できなかった。

v1.1.3と比較して、独自CSSの利用量や調整箇所は増えているが、画面全体として明確にデザイン品質が上がったとは評価できない。

さらに、実際のレンダリングでは、見出し `サービス状況` とその説明文が重なって表示される崩れが発生した。

この問題は、今回の検証において重要ではあるが、個別のCSS競合原因を掘り下げること自体が主題ではない。

本質は、**見た目を良くするために独自CSSの利用を明示的に広げたにもかかわらず、視覚品質が向上せず、一部ではむしろ劣化した**ことである。

したがって、v1.1.4の評価軸は「どのCSS指定が衝突したか」ではなく、Skill全体のデザイン誘導が有効だったかどうかとする。

## v1.1.4の根本的な失敗

今回の重要な観察は、独自CSSの量や個別実装技法ではない。

v1.1.4では、v1.1.3よりも独自CSSを積極的に使えるようにし、さらに余白、タイポグラフィ、情報階層、ヘッダー、状態表現、折り返し等を丁寧に調整するよう明示した。

それにもかかわらず、見た目は明確に向上しなかった。

つまり、問題は「CSSを使ってよいか」ではなく、**Skill全体がAIのデザイン能力をどう誘導しているか**にある可能性が高い。

ここで、これまでの整理軸そのものを見直す必要がある。

v1.1.1以降は、過去の失敗を一つずつ防ぐためにルールを追加・整理してきた。

その結果、要件遵守や表示ノイズ抑制は改善した一方、Skill全体の重心が「失敗しないための制御」に寄りすぎた可能性がある。

モデルにとっては、見た目を良くするための積極的な方向性より、禁止・抑制・境界条件の方が強く作用している可能性がある。

## v1.1.0の再評価

今回の結果を踏まえ、v1.1.0を改めて基準として見直す。

v1.1.0は、これまでの生成結果の中で依然として最も見た目の評価が高い。

v1.1.0には禁止事項も多いが、それと同時に、以下のような前向きなデザイン方向が強く書かれている。

- 無機質・陰気・平坦・事務的すぎる画面にしない
- 適度なメリハリ、テーマカラー、視線誘導、情報のまとまりを持たせる
- AIの情報設計やレイアウト提案を止めない
- ページ全体の構成、情報の優先順位、導線、カラム構成、ナビゲーション等を積極的に設計する
- Bulmaswatchテーマの色を積極的に活用する
- ページ全体の構図を設計する

この「目指す方向」が、v1.1.0の見た目の良さに寄与した可能性が高い。

一方、v1.1.0の主な問題は以下だった。

1. 同じ意味の指示が複数箇所で繰り返され、Skill自体が長く冗長だった
2. AIの裁量範囲が広く、画面要件以上のKPI、ナビゲーション、業務概念等まで膨らませる余地があった

つまり、v1.1.0の問題は「デザイン思想そのもの」ではなく、**重複した指示と要件境界の弱さ**だったと再整理する方が自然である。

## Skill設計の整理軸を見直す

今回までの検証では、失敗例が出るたびに個別ルールを追加し、Skillを精密化する方向へ進みすぎた可能性がある。

しかし、Webデザインの方向性については、細かな禁止事項を増やすよりも、AIに目指してほしい方向をある程度ぼんやり示す方が有効かもしれない。

今後は、Skill内の指示を以下の2種類に分けて考える。

### 強い禁止事項

明確に避けたいものだけを、具体的に書く。

例:

- 要件にない機能・データ・業務概念を勝手に追加しない
- データソースがない機能を、動いているように見せる架空処理で補完しない
- 絵文字をUIアイコンの代用品として使わない

この種のルールは、違反した場合に要件・実装上の問題が明確に発生するものに限定する。

### デザイン方向

見た目については、細かな禁止よりも方向性を示す。

例えば以下のような内容で十分と考える。

- 用途に合った、見やすく整ったUIにする
- 無機質・平坦になりすぎない
- 適度なメリハリを持たせる
- テーマカラーを活かす
- 情報の優先順位やページ全体の構図は積極的に設計する
- 必要に応じて独自CSSで仕上げる

この部分は、AIのデザイン探索空間を狭めすぎないことを優先する。

## コメント指示について

v1.1.4で唯一明確に成功した追加事項として、CSS / JavaScriptへのコメント指示がある。

今後も以下の原則は維持する価値がある。

- レイアウト意図
- 特殊な調整理由
- レスポンシブ時の特殊な挙動
- JavaScriptによる状態変更等

後から見て理由が分かりにくい部分には簡潔なコメントを入れる。

一方で、自明な処理への過剰なコメントは不要とする。

この指示は、見た目を制約せずに保守性だけを改善できるため、成功体験として次版へ引き継ぐ。

## 次版に向けた方向性

次版では、v1.1.4にさらにルールを追加するのではなく、v1.1.0を基準にSkillを再構成する。

基本方針は以下。

- v1.1.0の前向きなデザイン方向を基準にする
- 重複している指示を大幅に圧縮する
- 要件以上の機能・データ・業務概念を膨らませないという境界だけ明確に追加する
- デザインについての細かな禁止事項は減らす
- 独自CSSの利用は広く許容する
- CSS / JavaScriptへの簡潔なコメント指示は残す

つまり、次版の中心テーマは「さらに制御すること」ではない。

**v1.1.0で機能していたAIのデザイン裁量を戻しつつ、要件逸脱だけを防ぐこと**である。

現時点では、v1.1.0を成功基準として再評価し、その長所を圧縮して取り戻す方向が最も有望である。
